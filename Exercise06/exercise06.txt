Exercise 6: Exercise 3 with MPI_ANY_SOURCE
Run on: Debian Linux container (Docker), Open MPI 5.0.7, gcc 14.2, 8 cpus. Build: make   Run: make run

Rank 0 now receives with MPI_Recv(..., MPI_ANY_SOURCE, ...) instead of a fixed source,
and prints status.MPI_SOURCE to show which process each message came from.
(The sheet says "change the receiving Tag to MPI_ANY_SOURCE"; MPI_ANY_SOURCE replaces the
source argument, not the tag. The tag stays 0.)

Output:
received from:
processes = 1, pi = 3.141386, inside = 7853466, time = 0.131236 s
received from: 1
processes = 2, pi = 3.140890, inside = 7852224, time = 0.067516 s
received from: 2 1 3
processes = 4, pi = 3.141423, inside = 7853558, time = 0.034484 s
received from: 7 5 6 3 1 2 4
processes = 8, pi = 3.141721, inside = 7854303, time = 0.026776 s

Comparison with Exercise 3:
- pi and the inside count are exactly the same, because addition does not care about the
  order the counts arrive in.
- The order changes: Exercise 3 always received 1, 2, 3, ... With MPI_ANY_SOURCE rank 0
  takes whichever message arrives first (for example 7 5 6 3 1 2 4), and the order changes
  every run.
- The time is about the same or a little faster (0.027 s vs 0.028 s with 8 processes):
  rank 0 never waits for a slow rank while a faster rank's result is already waiting.
